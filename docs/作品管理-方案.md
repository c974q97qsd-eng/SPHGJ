## 零、约束落地总纲（v2 新增，先读这个）

| 约束 | 落地手段 |
|---|---|
| 图片本地化 | 封面下载到 `data/covers/<账号>/<作品ID>.jpg`，前端只请求本地静态路径，**永不直连 CDN** |
| 数据本地化 | 全字段 + 原始 JSON 入 SQLite，界面 100% 读本地库 |
| 不重复抓 | `cover_hash` 判重 + 翻页**早停** + 分层冷却期 |
| 压低请求量 | 手动刷新为主 + 刷新冷却 60s + 页数上限 + 写操作本地乐观更新（不回抓） |

**一句话**：官方接口只在「点刷新」时被打，且只打"可能有变化"的那部分；
图片只在"没有 / 换过"时下，且只下一次。之后所有浏览、搜索、排序、翻页，**零外部请求**。

## 二、现状盘点：什么能复用、什么要新做

### ✅ 可直接复用
- **发请求的通道**：`backend/api_client.py:107` `WxApiClient._post` —— 已登录浏览器上下文里
  `page.evaluate(fetch)`，自带节流（读 1–2.5s / 写 4–8s）、失败退避、每日写上限。
  视频号是**软签名**（同千川），写操作可直接调 API，不需 UI 点击。
- **封面下载通道（无需新增依赖）**：Playwright 的 `context.request.get(url)` —— 在**已登录
  context** 里发请求，自带 cookie + 可带 Referer，基本不会 403。**不用装 httpx / Pillow。**
- **分页抓取范式**：`post/post_list` 的 `lastBuff` 分页（`comment_fetcher.py:120`）。
- **账号 Worker**：每账号 `AccountWorker`，context 引用计数 + 全局串行锁 `_fetch_lock`
  （`account_manager.py:851`）。
- **存储模板**：`INSERT OR REPLACE` upsert（`storage.py:128`）、动态 where + 分页
  （`storage.py:184 query_comments`）。DB 目录已是 `data/`（`data/sphgj.db`）。
- **静态托管**：`server.py:1234` 已用 `StaticFiles` 挂 `/assets`，照搬挂 `/media/covers` 即可。
- **前端交互**：`CommentsPage.tsx` 批量勾选/全选/筛选/搜索照搬；网格照搬 `LiveScreenPage.tsx:38`。

### ❌ 要从零做
1. **作品列表字段**：现只用 `objectId` / `commentCount`，标题、封面、点赞、播放、
   隐藏状态**全部未知，需实测**。
2. **删除 / 隐藏 / 取消隐藏接口**：仓库零封装零记录。
3. **缩略图渲染**：项目**从未渲染过网络图片**。→ v2 改为本地文件，绕开防盗链问题。
4. **增量判定字段**：需要知道官方返回体里有没有 `update_time` / `modify_time`
   之类的变更标记（P0 探测重点确认；没有就用统计数字签名代替）。

```
【抓取（低频·手动触发）】

  前端作品管理页 ─▶ GET /api/posts（本地 SQL，搜索·排序·分页）─▶ SQLite
```

**核心原则：界面只读本地库 + 本地图片文件，不实时打任何外部接口。**

## 四、本地化与增量策略（v2 核心，本章最重要）

### 4.1 图片本地化（一次下载，永久复用）

- **存储**：`data/covers/<account_id>/<safe_object_id>.jpg`
  （`object_id` 做安全化：`re.sub(r'[^0-9A-Za-z_-]', '_', x)`）
- **服务**：`server.py` 加一行
  `app.mount("/media/covers", StaticFiles(directory=.../data/covers), name="covers")`，
  前端 `<img src="/media/covers/<account_id>/<id>.jpg">`，响应头 `Cache-Control: max-age=31536000`。
- **下载方式**：`context.request.get(cover_url, headers={"Referer": "https://channels.weixin.qq.com/"})`
  —— 走**已登录 context**，带 cookie，规避防盗链；**不占用账号的 API 请求配额**，
  也不受 `live_fetcher.py:104` 的图片拦截影响。
- **判重（关键）**：库里存 `cover_hash = md5(cover_url)[:16]`。
  - 本地文件存在 **且** `cover_hash` 未变 → **跳过，一次请求都不发**；
  - URL 变了（作者换封面）→ 才重新下载覆盖。
- **体积控制**：优先用 URL 自带的缩略图参数（如 `?wx_fmt=jpeg&tp=webp`）拿小图；
  单张上限 300KB，超出则降级存原图（不引 Pillow）。1000 条约 30–80MB，可控。
- **下载范围**：刷新时**只补下最近 300 条里缺失的**；更老的作品前端滚到视口时才触发
  （`GET /api/media/cover?account_id=&object_id=`：有文件直接返回，没有就下一次再返回）。
  → 既不卡首屏，也不会为了用不上的老作品浪费请求。

### 4.2 数据增量（避免重复抓）

**四道闸门，任一命中即停止本账号本轮翻页：**

| 闸门 | 规则 |
|---|---|
| ① **早停（主）** | 列表按时间倒序翻页。若整页作品都已入库 **且** `stat_sig` 未变 → 立刻停止，不再翻下一页 |
| ② **冷却期** | `<7 天` 的新作品：每次都更新；`7–30 天`：距上次 >24h 才更新；`>30 天`：**冻结**，只有手动「深度刷新」才动 |
| ③ **页数上限** | 每账号每次刷新最多 20 页（≈200 条）。首次全量可勾「拉到底」 |
| ④ **刷新冷却** | 距上次刷新 < 60s → 直接返回本地库并提示"xx 秒后可再刷新"，**不发请求** |

**`stat_sig`（统计数字签名）** = `md5(f"{play}|{like}|{comment}|{share}|{collect}")`。
作用有两个：翻页时判断"这页有没有变化"（决定要不要写库），以及作为早停依据。
只要官方返回体里没有可靠的 `update_time`，就用它。

**写操作 → 本地乐观更新，绝不回抓：**
删除成功 → 本地 `is_deleted=1`；隐藏 → `visible_status=1`；取消隐藏 → `0`。
**不为了"确认一下"再打一次接口**（数据正确性由下次自然增量顺带校验）。

### 4.3 请求量账本（给你一个直观预期）

| 场景 | 对官方接口次数 |
|---|---|
| 首轮全量（9 账号 × 20 页） | ≈180 次（**一次性**） |
| 日常点一次「刷新」（全部账号） | ≈10–20 次（早停生效后每账号 1–2 页） |
| 浏览 / 搜索 / 排序 / 翻页 / 换账号 | **0 次** |
| 看封面（已下载过） | **0 次**（本地文件 + 浏览器缓存） |
| 批量删除 50 条 | 50 次写请求（受 4–8s 节流，无法再压） |

对比"不本地化"的做法：每打开一次页面 = 上百次列表请求 + 上百张 CDN 图片请求。
**本地化后这两项直接归零。**

### 4.4 可观测（让你看得见消耗）
`post_fetch_meta` 表记录每个账号：`last_fetch_at` / `last_object_id` / `total_req` / `today_req`。
界面顶栏显示：`上次更新 12 分钟前 · 今日已请求 18 次`。
刷新按钮做成"有代价"的交互，避免手滑连点把请求量打上去。

## 五、数据模型（新增表）

```sql
CREATE TABLE IF NOT EXISTS posts(
  account_id    TEXT NOT NULL,
  object_id     TEXT NOT NULL,          -- 接口 objectId（与 exportId 同值）
  title         TEXT,                   -- desc.description（作品文案/标题）
  cover_url     TEXT,                   -- desc.media[0].coverUrl（仅判重与补下载用）
  cover_hash    TEXT,                   -- md5(cover_url)[:16]，判断是否换过封面
  cover_file    TEXT,                   -- 本地相对路径 data/covers/<account>/<hash>.jpg
  create_time   INTEGER,                -- 发布时间（unix 秒）
  duration      INTEGER,                -- videoPlayLen（秒）
  width         INTEGER,
  height        INTEGER,
  play_count    INTEGER DEFAULT 0,      -- readCount      播放
  like_count    INTEGER DEFAULT 0,      -- likeCount      点赞
  comment_count INTEGER DEFAULT 0,      -- commentCount   评论
  share_count   INTEGER DEFAULT 0,      -- forwardCount   转发
  collect_count INTEGER DEFAULT 0,      -- favCount       收藏
  follow_count  INTEGER DEFAULT 0,      -- followCount    新增关注
  yesterday_play INTEGER DEFAULT 0,     -- yesterdayReadCount
  full_play_rate REAL DEFAULT 0,        -- 完播率
  avg_play_sec   REAL DEFAULT 0,        -- 平均播放时长(秒)
  fast_flip_rate REAL DEFAULT 0,        -- 快滑率
  visible_type  INTEGER DEFAULT 1,      -- ★ 1=公开可见 / 2=仅自己可见（待实测确认 2）
  comment_close INTEGER DEFAULT 0,      -- 评论开关
  sticky_status INTEGER DEFAULT 0,      -- 置顶状态
  status        INTEGER DEFAULT 0,
  stat_sig      TEXT,                   -- 统计数字签名，增量早停用
  last_stat_at  TEXT,                   -- 上次更新统计的时间（冷却期用）
  raw           TEXT,                   -- 原始 JSON，字段变动可回溯，不用重抓
  updated_at    TEXT,
  PRIMARY KEY(account_id, object_id)
);
CREATE INDEX IF NOT EXISTS idx_posts_time    ON posts(create_time);
CREATE INDEX IF NOT EXISTS idx_posts_play    ON posts(play_count);
CREATE INDEX IF NOT EXISTS idx_posts_like    ON posts(like_count);
CREATE INDEX IF NOT EXISTS idx_posts_comment ON posts(comment_count);
CREATE INDEX IF NOT EXISTS idx_posts_share   ON posts(share_count);
CREATE INDEX IF NOT EXISTS idx_posts_collect ON posts(collect_count);
CREATE INDEX IF NOT EXISTS idx_posts_visible ON posts(visible_type);

-- 抓取账本
CREATE TABLE IF NOT EXISTS post_fetch_meta(
  account_id    TEXT PRIMARY KEY,
  last_fetch_at TEXT,      -- 上次刷新时间（冷却期判定）
  last_object_id TEXT,     -- 上次翻到的位置（早停锚点）
  total_req     INTEGER DEFAULT 0,
  today_req     INTEGER DEFAULT 0,
  today_date    TEXT       -- 用于跨天清零
);

-- 批量操作留痕
CREATE TABLE IF NOT EXISTS post_op_logs(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id TEXT, object_id TEXT, op TEXT,
  ok INTEGER, msg TEXT, ts TEXT
);
```

## 八、P0 接口探测结论（2026-09-15 实测，已完成）

### 8.1 正确入口与 base（关键，之前踩过坑）

| 页面 | URL | 接口 base |
|---|---|---|
| **内容管理-视频**（作品列表/管理） | `https://channels.weixin.qq.com/platform/post/list` | `https://channels.weixin.qq.com/micro/content/cgi-bin/mmfinderassistant-bin` |
| 评论管理（项目现用） | `https://channels.weixin.qq.com/micro/interaction/comment` | `https://channels.weixin.qq.com/micro/interaction/cgi-bin/mmfinderassistant-bin` |
| 认证 | — | `https://channels.weixin.qq.com/cgi-bin/mmfinderassistant-bin` |

⚠️ **两个坑**（都已实测验证）：
1. base 必须带 **`/cgi-bin`**，少了就返回 `Cannot POST`；
2. URL 必须带查询串 **`?_aid=<aid>&_pageUrl=<urlencode(当前页URL)>`**，否则返回 `errCode:300800`。
   `_aid` = `localStorage['__ml::aid']`（去掉引号），`_log_finder_id` = `localStorage['finder_username']`。

### 8.2 作品列表：`POST post/post_list`

请求体（官方前端实际发的）：
```json
{"pageSize":20,"currentPage":1,"userpageType":11,"stickyOrder":true,
 "timestamp":"<毫秒>","_log_finder_uin":"","_log_finder_id":"v2_xxx@finder",
 "rawKeyBuff":"","pluginSessionId":null,"scene":7,"reqScene":7}
```
响应：`errCode=0`，`data = {list, bindInfo, totalCount, lastBuff, continueFlag}`。
**实测该账号 totalCount = 2534，`pageSize` 可上调（官方默认 20）→ 这是压请求数的主要杠杆。**

**单条作品字段（34 个，已实测）**：

| 用途 | 字段 | 实测值 |
|---|---|---|
| ID | `objectId` / `exportId` | 同值，`export/UzFfAgtgekIEAQAA...` |
| 标题 | `desc.description` | "U.S. POLO ASSN. ..." |
| 发布时间 | `createTime` | unix 秒 |
| **播放** | `readCount` | 6054 |
| 昨日播放 | `yesterdayReadCount` | 0 |
| 点赞 | `likeCount` | 11 |
| 评论 | `commentCount` | 6 |
| 转发 | `forwardCount` / `forwardAggregationCount` | 34 |
| 收藏 | `favCount` | 45 |
| 新增关注 | `followCount` | 7 |
| 完播率 | `fullPlayRate` | 0.0565 |

| 封面 | `desc.media[0].coverUrl` / `thumbUrl` / `fullCoverUrl` | 带 token 的 CDN URL |

### 8.4 探测方法沉淀（比猜接口名高效得多）

猜接口名这条路**已经走死**（46 个候选 × 2 base 全 `Cannot POST`）。有效方法是：

1. **`tools/sniff_posts.py` / `sniff_postlist.py`**：不自己构造请求，只监听官方前端自己发的包
   → 零额外请求、字段 100% 真实。前提是**先停引擎**释放 profile。
2. **`tools/scan_js_apis.py`**：把页面加载的 JS bundle 里所有 `xxx/yyy` 形式的接口路径正则抽出来

   `post/post_update_visible`。**这是找写操作接口的最短路径。**

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| 接口字段 / 名称未知 | P0 先探测；`raw` 存原始 JSON，改字段不用重抓 |
| 返回体无 `update_time` | 用 `stat_sig` 代替做早停判定（方案已内置兜底） |
| 删除/隐藏需要一次性 token 或只能 UI 点击 | 先试 API；不行退回 UI 点击，或本期只做隐藏不做删除 |
| 封面 403 | 走 `context.request.get`（带 cookie + Referer）；仍失败则该条用占位图，不重试 |
| 图片被 CDP 拦 | `live_fetcher.py:104` 拦了图片 → 封面下载走 `context.request`，**不经过页面加载** |
| 风控 | 4–8s 节流 + 每日写上限 + 失败退避 + 刷新冷却 + 页数上限 |
| 本地库与官方不一致（官方侧手改了） | 提供「深度刷新」手动兜底；自然增量会逐步收敛 |
| 磁盘占用 | 封面压到 300KB 内；提供"清理 N 天前未访问封面"的维护入口 |
